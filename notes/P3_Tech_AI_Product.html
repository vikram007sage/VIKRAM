01 / WEB

What happens when you open an app or URL

core
DNSThe domain name is looked up to find the server's IP address (cached by browser, OS, ISP).
ConnectionTCP connection + TLS handshake (HTTPS encryption with certificates).
CDNStatic files (images, scripts) often served from a nearby content delivery network edge.
Load balancer → app serversRequest routed to one of many servers running the backend code.
Cache → databaseServer checks a cache (e.g. Redis) and then the database; builds a response.
ResponseJSON (for an app) or HTML; the client renders it. Each step adds latency — users notice above ~100–300 ms for interactions.

APIs

A contract for how software talks: REST (resources + HTTP verbs GET/POST/PUT/DELETE, JSON), GraphQL (client asks for exactly the fields it needs), webhooks (server calls you when something happens, e.g. payment success). Status codes: 200 OK, 400 bad request, 401 unauthorised, 404 not found, 429 rate-limited, 500 server error.

Databases

SQL/relational (Postgres, MySQL): structured, transactions, strong consistency — payments, orders. NoSQL (MongoDB, DynamoDB, Cassandra): flexible schema, horizontal scale — feeds, logs, catalogues. Vector databases: similarity search over embeddings (M3).

Front end vs back end

Front end: what users see (web, Android, iOS, or cross-platform like React Native/Flutter). Back end: business logic, data, integrations. Native apps need app-store releases; web and server changes ship instantly — this affects how fast you can experiment.

03 / PAYMENTS

How UPI and card payments flow

fintech

UPI

Payer app (PSP, e.g. PhonePe/GPay) → payer's PSP bank → NPCI UPI switch → payee's bank → credit; confirmation back through the chain, usually in seconds. Uses a virtual payment address (VPA); authorised with UPI PIN. Zero merchant discount rate for most person-to-merchant UPI. Failures often come from a bank's server being down — success rates are tracked per bank.

Cards

Customer → merchant → acquirer (merchant's bank / payment aggregator like Razorpay) → card network (Visa, Mastercard, RuPay) → issuer (customer's bank) approves → settlement later (T+1). The merchant pays the MDR, split among issuer (interchange), network and acquirer. RBI rules: card tokenisation (no storing card numbers), additional factor of authentication for domestic online payments.

RuPay credit on UPI

RuPay credit cards can be linked to UPI, bringing credit to QR payments. Small-value merchants typically pay no MDR on small transactions; issuers earn interchange on larger ones. Important for card growth among young users (B1).

04 / AI

Building AI features as a PM

core
ApproachWhenTrade-off
Prompting a hosted LLM via APIFirst version of most featuresFast to build; per-call cost; data leaves your system (check terms)
RAG (retrieval + LLM)Answers must use your documents/data (FAQs, policies, product catalogue)Quality depends on retrieval; easier to update than fine-tuning (M3)
Tools / agents (function calling, MCP)The model must act: check order status, book, file a ticketMore powerful, more risk; needs permissions and human approval for sensitive actions
Fine-tuning a modelConsistent style/format at scale, a narrow task, or cost reduction with a small modelNeeds good labelled data; harder to update
Classical MLPrediction on structured data: fraud, credit risk, churn, rankingCheaper, explainable, well understood (M1)
RulesClear logic, complianceBrittle but predictable
Cost mathsCost per call = (input tokens × input price + output tokens × output price) ÷ 1,000,000. Example: a support bot uses 3,000 input + 400 output tokens per answer at $2/$10 per million → $0.006 + $0.004 = $0.010 ≈ ₹0.85. At 1 lakh chats/day ≈ ₹85,000/day. A smaller model at a tenth the price, or caching, may make the feature profitable.
LatencyTime to first token and total time; stream responses; use small models for simple steps.
QualityBuild an eval set before launch (100–500 real examples with expected answers); measure accuracy, hallucination rate, refusal rate; online: resolution rate, escalation to human, CSAT (M3).
RisksHallucination, prompt injection (malicious text in documents or web pages instructing the model), data privacy (India's DPDP Act), bias, over-reliance; mitigate with grounding, permission limits, human review, logging.
2026 context: frontier models from OpenAI, Google, Anthropic and others release every few weeks; open-weight models (Qwen, DeepSeek, Llama, Kimi and others) are competitive for many tasks. Agents connect to tools through standards such as the Model Context Protocol (MCP, created by Anthropic in Nov 2024 and since adopted by OpenAI, Google and Microsoft; ~97 million monthly SDK downloads by March 2026) and agent-to-agent protocols such as Google's A2A. Say "I'd pick the model by evaluating 2–3 on our own eval set for quality, cost and latency" rather than naming a favourite.
