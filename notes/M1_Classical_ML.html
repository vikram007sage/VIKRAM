02 / FUNDAMENTALS

Bias–variance and regularisation

Expected error = Bias² + Variance + Irreducible noise

High bias (underfit)

Training and validation error both high. Fix: richer model, more features, less regularisation, train longer.

High variance (overfit)

Training error low, validation error high. Fix: more data, simpler model, regularisation, dropout, early stopping, bagging, feature selection.

Learning curves

Plot train/validation error vs training size. Gap that closes with more data → variance (get data). Both plateau high → bias (change model).

L1 (Lasso)L2 (Ridge)
Penaltyλ Σ|w|λ Σw²
EffectPushes some weights to exactly 0 → feature selectionShrinks all weights smoothly; handles correlated features
UseMany features, want a sparse modelMulticollinearity, default choice

Elastic Net mixes both. In trees, regularisation = max depth, min samples per leaf, learning rate, subsampling, number of trees with early stopping.

03 / METRICS

Choosing and reading metrics

most asked
Precision = TP ÷ (TP + FP)  ·  Recall = TP ÷ (TP + FN)  ·  F1 = 2PR ÷ (P + R)  ·  Accuracy = (TP + TN) ÷ all

Worked: 1,000 transactions, 20 are fraud. The model flags 40, of which 16 are fraud. Precision = 16/40 = 40%; recall = 16/20 = 80%; F1 ≈ 0.53; accuracy = (16 + 956)/1000 = 97.2% — but a model that flags nothing scores 98% accuracy. Accuracy is useless on imbalanced data.

ProblemMetricWhy
Fraud, disease (rare, costly misses)Recall at acceptable precision; PR-AUCMissing fraud is expensive; ROC-AUC looks flattering when positives are rare
Spam filter, marketing offers (costly false alarms)PrecisionAnnoying good customers costs more
Ranking risk (credit scoring)ROC-AUC / Gini, KSThe lender sets the cut-off later
RegressionMAE (robust, in units), RMSE (punishes big errors), MAPE (relative; breaks near zero)Pick what matches the business cost
ForecastingMAPE/WAPE on a later time windowTime-ordered validation

Credit-risk model metrics (Amex, Capital One, banks, fintechs)

ROC-AUCProbability a random defaulter is scored riskier than a random good borrower. 0.5 = random, 0.7–0.8 typical for application scorecards.
Gini= 2 × AUC − 1. AUC 0.75 → Gini 0.50. Banks usually quote Gini.
KS statisticMaximum gap between cumulative % of bads and goods across score bands; higher = better separation (30–50 is common).
PSIPopulation stability index: has the score distribution shifted since development? <0.1 stable, 0.1–0.25 watch, >0.25 investigate/retrain.
CalibrationDo predicted PDs match actual default rates by band? Needed for pricing and ECL provisioning (B1).
04 / HONESTY

Validation, leakage and imbalance

core

Splits

Train / validation / test. k-fold cross-validation for small data (stratified for classification). Time-based split for anything with time (train on Jan–Jun, test on Jul–Aug). Grouped split when a customer appears many times.

Leakage

Information from the future or the label sneaking into features: "number of collection calls" predicting default, scaling on the full dataset before splitting, target encoding without folds. Symptom: suspiciously high validation scores that collapse in production.

Imbalance

Use the right metric first. Then class weights, threshold tuning, or resampling (undersample majority, SMOTE) — only on training data, never the test set.

Hyperparameter tuningGrid (small spaces), random search (better per trial), Bayesian optimisation (Optuna; same idea as your GP optimiser).
ThresholdThe 0.5 cut-off is arbitrary. Choose the threshold that minimises expected business cost (cost of a missed fraud vs a false alarm).
DriftData drift (inputs change: new customer mix after a RuPay-on-UPI push) and concept drift (relationship changes: a recession). Monitor PSI and performance; retrain on a schedule.
05 / ENSEMBLES

Trees, bagging and boosting

Decision tree

Splits on the feature/threshold that most reduces impurity (Gini impurity or entropy for classification, variance for regression). Greedy; deep trees memorise.

Bagging → Random forest

Train many deep trees on bootstrap samples, each split choosing from a random subset of features; average them. Reduces variance. Out-of-bag error gives free validation.

Boosting

Train shallow trees sequentially, each fitting the residual errors (gradients) of the ensemble so far; learning rate shrinks each step. Reduces bias. XGBoost adds regularisation; LightGBM is fast (histogram, leaf-wise); CatBoost handles categoricals well.

Feature importance: built-in split importance is biased toward high-cardinality features. Prefer permutation importance or SHAP values, which also explain individual predictions ("this applicant was declined mainly because of high utilisation and 2 recent enquiries") — useful for credit adverse-action reasons.
06 / UNSUPERVISED

Clustering, PCA and feature engineering

k-meansAssign points to nearest centroid, move centroids, repeat. Choose k with the elbow method or silhouette score; scale features first. Use: customer segments by spend mix.
DBSCANDensity-based; finds arbitrary shapes and flags noise points (anomalies); no k needed.
PCARotates data to orthogonal directions of maximum variance; keep components explaining ~90–95% of variance.
Feature engineering (tabular)Ratios (utilisation = balance ÷ limit), recency/frequency/monetary, rolling windows (spend last 30/90 days), trends (this month vs 3-month average), counts (enquiries in 6 months), date parts, target/frequency encoding for categories.
ScalingNeeded for distance and gradient-based models (k-NN, SVM, linear, neural nets); not for trees.
Missing valuesImpute (median, model-based) and add a "was missing" flag — missingness itself is often predictive (no salary info).

08 / CASE

Mini case: build a card-churn model

DefineChurn = no spend for 90 days or card closed within the next 90 days; score monthly.
DataSpend trends, category mix, rewards balance, fee due date, complaints, utilisation, tenure, competitor offers (if known). Only features available at scoring time.
ModelLogistic baseline + LightGBM; time-based validation; PR-AUC and lift in top decile.
ActionTarget the top-risk decile with retention offers; but use an uplift test (D3): some would stay anyway, some leave regardless.
MeasureA/B test the intervention; track saved spend net of offer cost; monitor PSI monthly.
