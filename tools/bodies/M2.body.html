00 / ORIENTATION

The one-paragraph picture

A large language model is a transformer network trained to predict the next token. Text is split into tokens, each token becomes a vector, stacked attention and feed-forward layers mix information across positions, and the final layer gives a probability for every token in the vocabulary. Generating text is sampling one token at a time and feeding it back in. Chat behaviour comes from further training on instructions and human (or AI) preferences.

01 / INPUT

Tokens and embeddings

core
TokenisationText → sub-word pieces using byte-pair encoding (BPE) or similar. In English ~1 token ≈ ¾ of a word; Hindi and other Indic scripts often need more tokens per word with many tokenisers, so the same text costs more and fills context faster (a reason Indic-first models such as Sarvam's focus on tokenisers).
VocabularyTypically 32k–200k tokens. The final layer outputs one score (logit) per vocabulary token.
EmbeddingEach token id looks up a learned vector (e.g. 4,096 numbers). Similar meanings end up close together.
PositionAttention has no sense of order by itself, so position is added: original sinusoidal encodings, learned positions, or today's common rotary embeddings (RoPE), which rotate query/key vectors by position and extend better to long context.
02 / ATTENTION

Self-attention, worked by hand

most asked
Attention(Q, K, V) = softmax(Q KT ÷ √dk) V
Q, K, VEach token's vector is multiplied by three learned matrices: query (what I'm looking for), key (what I contain), value (what I pass on).
ScoresDot product of a query with every key = relevance; divide by √dk so large dimensions don't push softmax to extremes.
WeightsSoftmax turns scores into weights summing to 1.
OutputWeighted sum of value vectors.
Causal maskIn a decoder (GPT-style), each token can only attend to itself and earlier tokens — that's what makes next-token prediction honest.
Tiny example (3 tokens, d = 2, no mask)

Q = K = [[1,0],[0,1],[1,1]]; V = [[1,2],[3,4],[5,6]]. For token 1: scores with keys = [1, 0, 1] ÷ √2 → softmax ≈ [0.40, 0.20, 0.40] → output ≈ 0.40·[1,2] + 0.20·[3,4] + 0.40·[5,6] = [3.0, 4.0]. Token 3 (query [1,1]) scores [1,1,2] ÷ √2 → weights ≈ [0.25, 0.25, 0.50] → output ≈ [3.51, 4.51]: it attends most to itself because its key matches best.

Multi-head

Several attention operations in parallel with different Q/K/V projections (one head may track syntax, another coreference); outputs concatenated and projected.

Efficient variants

Grouped-query attention (GQA) shares keys/values across heads to shrink memory; FlashAttention computes the same result with less memory traffic; sliding-window and sparse attention for long context.

Cost

Attention over n tokens costs O(n²) compute per layer — doubling context roughly quadruples attention cost, one reason long context is expensive.

03 / ARCHITECTURE

The transformer block and model families

Blockx → LayerNorm → multi-head attention → add residual → LayerNorm → feed-forward network (expand ~4×, non-linearity such as SwiGLU, project back) → add residual. Stack 30–100+ blocks.
Residual connectionsLet gradients flow through deep stacks; each block adds a refinement.
OutputFinal vector × vocabulary matrix → logits → softmax → next-token probabilities.
Mixture of experts (MoE)Feed-forward layer split into many "experts"; a router sends each token to a few. Total parameters large, active parameters per token small — much of today's frontier and open-weight models (e.g. DeepSeek, Qwen, Kimi) use MoE.
FamilyExamplesUse
Encoder-onlyBERT, RoBERTaClassification, embeddings, search
Decoder-onlyGPT, Claude, Gemini, Llama, Qwen, DeepSeekGeneration, chat, reasoning — the dominant design
Encoder–decoderT5, original TransformerTranslation, summarisation
MultimodalVision encoder + LLM, or natively multimodalImages, audio, video inputs
04 / TRAINING

How a chat model is trained

core
1. Pre-trainingNext-token prediction (cross-entropy loss) on trillions of tokens of web, books, code. Compute ≈ 6 × parameters × tokens FLOPs: a 7-billion-parameter model on 2 trillion tokens ≈ 8.4 × 10²² FLOPs. Scaling laws: loss falls predictably with more compute; "Chinchilla" suggests ~20 tokens per parameter for compute-optimal training, though modern models train far longer to make smaller models stronger.
2. Supervised fine-tuning (SFT)Train on (instruction, good response) pairs so the model follows instructions and chats.
3. Preference trainingRLHF: humans rank responses → train a reward model → optimise the policy with RL (PPO) while staying close to the SFT model (KL penalty). DPO: skips the reward model, trains directly on preferred vs rejected pairs. RLAIF / constitutional methods use AI feedback guided by written principles.
4. Reasoning RLSince 2024–25, models are trained with reinforcement learning on tasks with checkable answers (maths, code, tests) to produce long chains of thought before answering ("reasoning" or "thinking" models). Spending more tokens thinking at inference ("test-time compute") improves hard-problem accuracy.
5. Safety + evaluationRed-teaming, refusal training, benchmark and capability evaluations before release.
Interview line: "Pre-training gives knowledge and language; fine-tuning gives behaviour; preference and reasoning RL give helpfulness and problem-solving."
05 / INFERENCE

Decoding, cost and the KV cache

practical
GreedyAlways pick the most likely token: deterministic, can be repetitive.
TemperatureDivide logits by T before softmax. Logits [2, 1, 0]: T = 0.5 → [0.87, 0.12, 0.02]; T = 1 → [0.67, 0.24, 0.09]; T = 2 → [0.51, 0.31, 0.19]. Low T = focused, high T = varied.
Top-k / top-pSample only from the k most likely tokens, or the smallest set whose probabilities sum to p (nucleus sampling).
Prefill vs decodePrefill processes the whole prompt in parallel (fast per token); decode generates one token at a time (slower) — that's why output tokens cost more than input tokens.
KV cacheKeys and values of previous tokens are stored so they aren't recomputed. Memory per token ≈ 2 × layers × hidden size × bytes: for 32 layers, 4,096 hidden, 16-bit → ~0.5 MB per token, ~4 GB for 8,000 tokens (GQA reduces this a lot). Long context is memory-hungry.
Speed tricksBatching, speculative decoding (a small model drafts, big model verifies), prompt caching (reuse a repeated system prompt), quantisation, distillation into smaller models.
06 / ADAPTING

Prompting, fine-tuning, LoRA and quantisation

MethodWhat changesWhen
Prompting / few-shotNothing in the modelAlways try first
RAGContext given at query timeKnowledge that changes or is private (M3)
Full fine-tuningAll weightsRarely, for big shifts; expensive
LoRA / QLoRASmall low-rank matrices added to weight layers (W + BA, rank 8–64); QLoRA does this on a 4-bit modelStyle, format, narrow tasks on a budget; one GPU can tune a 7B model
DistillationTrain a small model on a big model's outputsCheaper, faster production model
QuantisationStore weights in fewer bits. 7B parameters: 16-bit ≈ 14 GB, 8-bit ≈ 7 GB, 4-bit ≈ 3.5 GB — fits on a laptop GPU, small quality loss.
Why LoRA worksThe change needed for a task is approximately low-rank; training ~0.1–1% of parameters gets most of the benefit.
07 / LIMITS

Why models fail

Hallucination

The model produces fluent but false text because it's trained to produce likely text, not verified truth. Mitigate with retrieval, citations, asking it to say "I don't know", verification steps.

Knowledge cutoff

Training data stops at a date; use search or RAG for current facts.

Prompt injection

Instructions hidden in retrieved documents, emails or web pages can hijack an agent. Separate trusted instructions from untrusted data, limit tool permissions, require confirmation for actions.

Bias and sycophancy

Models can reflect training-data bias or agree with the user too readily; evaluate on diverse cases.

Tokenisation quirks

Counting letters, arithmetic on long numbers; use tools (a calculator or code) for exact work.

Long-context degradation

Information in the middle of very long prompts can be used less reliably; put key instructions at the start or end and test.
